# 旧编号与当前维护阶段

此处对照改造前的编号脚本流程。保留旧流程的数据职责，不回退已有的分页覆盖校验、持久化队列、访问错误分类和原子保存。

| 旧步骤 | 数据与来源 | 当前对应 |
|---|---|---|
| 1 | 按年抓出版物目录，写入 `publicationInfo/Journals`、`publicationInfo/Conferences` | `--stage catalog` 的目录抓取部分 |
| 2 | 归并目录和历史名称，生成 `all_journals.json`、`all_conferences.json` | `catalog` 内置归并；兼容的编号 2 脚本仍保留本地归并逻辑 |
| 3 | 根据出版物目录抓论文基础字段，写入 `articleInfo` | `--stage metadata` |
| 4 | 逐篇打开 `/document/{articleNumber}`，读取 `xplGlobal.document.metadata` 中的摘要和分类关键词 | `--stage enrich` |

第 1、3、4 个编号入口已改为统一 CLI 的兼容入口；新 `catalog` 会在抓取成功后直接更新归并索引，并不与旧脚本逐行相同。目录增量发现、未来年份处理、覆盖检查、重试和恢复也做过改造。本文恢复的是第 3、4 步的来源边界。

## 第 3 步只更新基础字段

从搜索结果保留论文编号、出版物编号、DOI、年份和日期、标题、卷期、页码、出版者、内容类型、出版物名称，以及保持顺序的作者字段。

无论搜索返回的摘要看起来长还是短，第 3 步都不接收 `abstract` 或 `keywords`，不能据此将这两个字段标为完成。这个约束同时作用于搜索结果解析和入库边界，防止其他版本的 worker 携带摘要字段进入基础更新。

新论文的摘要和关键词状态为待补。已有论文在文献页阶段取得的值及状态保持不变；第 3 步不能把一个已有缓存值从待补提升为完成，也不会删除已有的完整摘要或关键词。因而 `articleInfo` 文件可以保留上次第 4 步写入的字段，这不表示第 3 步重新采集了它们。

当前响应没有返回、但仍保留在历史 JSON 中的论文，只维护文件关联并补入尚未入库的基本记录，不用旧缓存覆盖数据库已有字段。当前响应中的非空基本字段更新数据库；来源暂未返回的字段保留数据库已有值，并把合并后的基本字段同步到该响应对应的快照。摘要与关键词仍保持各自阶段的边界。

## 第 4 步负责摘要和关键词

按论文编号访问文献页，读取与旧第 4 步相同的 `xplGlobal.document.metadata` 来源。有效响应中的摘要与关键词分别更新，并同步 MySQL 和对应 JSON；关键词保留分类。已有空值仍要补查。访问受限、意外页面和解析失败不能被当作来源无数据。

旧第 4 步的跳过条件是“已有摘要或已有关键词就跳过整篇”，会漏补另一个字段。这一缺陷不恢复：当前按两个字段各自的状态决定是否检查。

历史 JSON 导入时，已知的 400 字符预览签名标为待补；没有省略号的短摘要不能仅因长度被当作截断。文献页本身若确认返回短摘要，由第 4 步记录其结果，后续基础信息更新保留该决定。

## 全量与增量中的 Early Access 复查

从 0.5.3 起，新建的 `--stage all` 和 `--stage metadata` 任务在普通论文分片抓取之后，自动增加
`early_access` 阶段；`--verify-all` 全量核对与普通增量更新均包含此阶段，无需额外命令。
目录阶段和单独的摘要、关键词阶段不增加这项工作。

此阶段选择当前范围内仍为 Early Access 的全部论文，不采用历史分片的 30 天跳过规则。
未指定年份时，包含该出版物所有历史年份的 Early Access。指定年份时，按既有 JSON 文件归属
选择论文；会议年份按出版物目录中的届次归属。选入后直接访问 `/document/{articleNumber}`
中的当前文献元数据，不再用旧年份过滤响应。因此，原属 2023 年的论文即使正式发表年份已
变成 2025 年，也会更新原编号的数据库记录。

按编号读取的字段仍限于基础信息：出版状态、标题、作者、日期、卷期和页码等。页面中即使
同时含摘要和关键词，也不接收这两个字段，不改变它们的完成状态。数据库保留一条当前论文
记录；对应已有 JSON 中该编号的基本字段同步更新，文件路径、其他论文和已有摘要、关键词
保留。旧内容由现有原子导出及备份机制保存；不会据此创建一个覆盖不完整的新年份分片。

同一任务内每个编号只复查一次。仍为 Early Access 的论文会在下次更新时再次选入；已确认
正式卷期的论文退出这项复查。访问受限、解析失败、编号不符不能作为已正式发表或来源无数据。
已核实的正式基础信息不会被旧 Early Access 的 `PP/99` 等临时字段覆盖。

`status` 的 `early_access` 项分别返回选中、完成、转正式、仍为 Early Access、待处理、运行中、
失败和受限数量。SQL 应用与 JSON 导出分开留有恢复状态，导出失败时不会重复计数或丢弃旧内容。

只有新提交任务的参数中会写入 `early_access_refresh`。旧任务在新版本下恢复时保持原有范围
和流程，不自动插入新阶段。升级代码也不会自动重启、重新安装或改写一个已在运行的任务。
