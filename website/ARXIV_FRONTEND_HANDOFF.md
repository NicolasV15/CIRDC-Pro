## 本轮工作与边界

1. 在同样的主题、语言、窗口宽度和阅读设置下对比 IEEE 与 arXiv。列出真实问题及其位置；下面是检查方向，不是已确认的缺陷。
2. 修缮搜索栏与筛选换行、结果密度、标题与作者排版、摘要折叠、信息栏、按钮排列、弹窗、空态、错误及加载反馈。覆盖长标题、长作者、公式标题/摘要和窄屏。
3. 检查从搜索进入详情再返回、来源切换、版本切换、刷新和前进后退；版本变化时不得短暂串用旧版本正文、链接或状态。可根据实际需要改进或扩展检索与浏览能力，并明确新增行为、数据依据和验收方式。
4. 统一获取、排队、部分成功、确认缺失、受限、失败和重试的文案与可用操作。缓存下载只读；批量 ZIP 的显式 POST 是打包已有文件，不能变成上游获取。
5. 优先复用共享组件和样式；可以按自己的审美优化视觉细节与交互组织，保留 IEEE 的整体风格。避免重复建设视觉系统或堆砌说明卡片。共享组件修改必须同时回归 IEEE。
6. 不把上述检查项当作开发上限。发现有价值的功能缺口时，可以自行设计并实现相关功能及必要的公共 API 支持；在交付中说明解决的问题、设计理由和验证结果。

以下契约必须保留：

- 普通搜索、打开页面、切换版本、刷新、轮询和下载已有缓存不触发采集、转换或全库任务；仅用户明确点击获取/重试才请求对应资料。

- 本轮允许前端优化、功能新增及配套公共 API 开发，范围围绕 arXiv 的检索、浏览与阅读体验。元数据初始化/增量、私有 worker、模型调用和其他仓库不因这项授权自动启动或改动；需要这些能力时先明确依赖与另行授权边界。

- **旧版本说明**：查看非最新版本时，注明标题、作者和摘要是当前元数据，不一定与该版本相同。

### 设计理由

- 资料状态按「原件 + 正文」逐项列出，状态徽标复用后台已有的颜色语义。页面上能触发上游获取的只有一个按钮，文字随状态变化，避免把「下载」和「获取」混在一起。
- 版本是阅读的主要维度，所以从侧栏移到标题下方，侧栏只显示当前版本和版本数。
- 快捷分类对应 IEEE 的精选刊会：电路方向的 arXiv 论文主要分布在这几个子类。

### 未验证与尚存问题

- 没有连接真实的 arXiv 元数据库、索引、资源提供方或线上站点；全部结果来自 fixture。大类筛选在完整索引上的速度没有测量。
- 元数据文档里是否有备注、期刊引用等字段，以及键名的写法，都没有用真实数据核对。另外，后端 `Catalog.paper()` 会去掉以 `_ref` 结尾的键；如果真实数据把期刊引用存为 `journal_ref`，它不会传到前端。本轮没有改动这一规则。
- 「受限」状态是否会被 `retry` 重新尝试，是根据接口文档推断的，需要在真实资源提供方上确认。
- `document.source` 只确认了 `arxiv_html`、`arxiv_source` 和 `pdf_parse` 三种取值；其他取值仍显示为「官网正文」。
- 只测了 Chrome；Safari、Firefox 和非 macOS 字体没有检查。
